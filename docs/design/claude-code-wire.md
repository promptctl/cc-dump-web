# What Claude Code says on the wire about its agents

Where a subagent stands and whether it runs are read from these facts alone (`packages/ui/src/format/wire.ts`). Each was measured on a recording in `~/.local/share/cc-dump/recordings/` or read from the Claude Code binary, as its line says. `node packages/ui/check/requests.ts <recording>` prints each request of a recording as one JSON line, its `x-claude-code-*` headers and its decoded body, and the commands below read that output, `$R` being the recording.

- **Who sent a request.** The main agent's requests carry no `x-claude-code-agent-id`. A subagent's requests carry its id there, and a subagent launched by another subagent also carries that one's id in `x-claude-code-parent-agent-id`. A subagent launched by the main agent carries no parent. In 20261117T143819.271Z, 112 requests carry neither, 72 carry an agent id alone, and 7 carry both, whose parent `a7843e6799a4769b8` sent requests of its own first: `node packages/ui/check/requests.ts $R | jq -c '.headers | map(.[0])' | sort | uniq -c`.
- **A background agent's result names it as it starts.** It is a text that opens `Async agent launched successfully.` and holds a line `agentId: <id> (internal ID - do not mention to user.…`. Measured in 20261117T143819.271Z: `… | grep -o 'Async agent launched successfully[^"]\{0,240\}'`.
- **A foreground agent's result names it as it returns.** Its report ends with a trailer on lines of its own: `agentId: <id>`, then ` (use SendMessage with to: '<id>', … to continue this agent)` where it can be continued, then `worktreePath:` and `worktreeBranch:` lines where it ran in a worktree, then `<usage>subagent_tokens: …</usage>`. The trailer is the last text of the result, or is appended after a line break to a report of one text. An agent of some types returns its report bare, naming nothing. No recording holds one yet: this is read from the JavaScript bundled in the Claude Code 2.1.299 binary, where the trailer is the template literal that begins `` `agentId: ${n.agentId}${B}${h} ``.
- **A forked Skill's result names no agent.** It says `Skill "<name>" launched (forked execution, running in the background).` The agent it forks is named by its notification, with the Skill call's id. In 20261117T061710.346Z, the notification for `a330dd041da201c30` names `toolu_01UigwjTehkBMDnT87ywpcLo`, a Skill call: `… | grep -o 'launched (forked execution[^"]\{0,60\}'`, then `… | grep -o '<task-notification>\\n<task-id>[a-z0-9]*</task-id>\\n<tool-use-id>[^<]*' | sort -u` and `… | grep -o '"id":"toolu_[A-Za-z0-9]*","name":"Skill"' | sort -u`.
- **A task notification tells that an agent stopped.** It is a `<task-notification>` element on lines of its own, in a system reminder of a user message or in a system-role message's text. Its `<task-id>` comes first and names the agent. A `<tool-use-id>` naming the launching call follows only sometimes. In 20261117T143819.271Z the notifications of eleven agents have one, and those of `a7843e6799a4769b8` and `a6787ff8b38e6890b`, both completed and both named by their launch's result, never do. In 20261118T092150.474Z none of the three do: `aeb0927abd04e4d83` and `ae8d8dc233688f41a` were killed, and `a2ac9933c7004d07a` completed. Measured with `… | grep -o '<task-notification>\\n<task-id>[a-z0-9]*</task-id>\\n<[a-z-]*>' | sort | uniq -c`. A request resends the notifications of the history it sends, so only the first request to send one tells its stop. In 20261118T092150.474Z, the first to send `aeb0927abd04e4d83`'s holds it in the first of its two messages.

In 20261117T143819.271Z, 56 requests ask: `… | grep -c 'Describe your most recent action'`.
